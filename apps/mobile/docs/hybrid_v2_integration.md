# QuillGrade Hybrid V2 integration

Implemented incrementally in the existing Flutter application on 2026-10-18.

This report records the original manual-input Hybrid V2 integration. The subsequent [automatic diameter integration](diameter_v1_integration.md) adds an optional experimental estimate, schema version 3, and updated verification results. Manual caliper input remains available. The original analyzer notices recorded below were resolved in the subsequent cleanup.

## Architecture and resulting workflow

The existing MLService returned simulated grades, dimensions, circularity and oil estimates. It now loads the supplied Hybrid V2 configuration/model and performs real native TFLite inference. It never synthesizes a successful prediction. The installed tflite_flutter dependency remains ^0.12.1.

The capture controller still requires VALID results from CinnamonValidatorService for both photos. Its failure, uncertainty, retry, retake and cancellation gates remain in place. The cinnamon validator service, preprocessing, threshold, model and labels were not edited for this integration.

After both photos pass:
1. The existing scan screen opens a themed caliper-entry dialog.
2. The user enters a finite positive diameter in millimeters. No diameter is estimated from images.
3. Predict Grade runs real Hybrid V2 inference in a worker isolate, keeping the camera UI responsive.
4. The user sees the predicted class, raw softmax model probability and Experimental Prediction label.
5. Confirm & Save creates the sample transactionally. Editing the measurement invalidates the displayed prediction and requires inference again.

No record is created for rejected photos, missing/invalid measurements, failed inference, or unconfirmed predictions. Errors retain the validated photos for retry. Retake End Photo preserves the valid side photo. Cancel invalidates late results and cleans uncommitted photo files. Repeated grading and save taps are guarded.

The existing result screen and home/history lists now use the stored manual diameter. The hard-coded 98% Optical Confidence and invented fallback dimensions were removed from this path. Height remains null and displays Not measured. Existing historical measured dimensions are still displayed when present.

## Preprocessing verification and limits

The supplied Colab code specifies EXIF transposition, RGB conversion and PIL ImageOps.pad to 224x224 with BILINEAR filtering and white padding. Hybrid preprocessing is separate from the cinnamon validator's preprocessing.

The implementation includes antialiased separable bilinear resizing, aspect preservation, centered padding, RGB channel order, and EXIF orientations 1 through 8 for JPEG and PNG. Full-resolution buffers use Uint8List to avoid a boxed integer allocation for every color channel.

21 synthetic reference cases were generated by executing the supplied preprocessing with Pillow 13.0.0:
- landscape/portrait downsampling, upsampling, square input and alpha removal;
- all eight JPEG EXIF orientations;
- all eight PNG EXIF orientations.

PNG output is tested pixel-for-pixel. JPEG allows at most 3 RGB levels of decoder rounding difference. White padding remains 255. These are preprocessing fixtures, not grading-accuracy or real-model-output fixtures.

Pillow version matters: [Pillow 13's resampler](https://github.com/python-pillow/Pillow/blob/13.0.0/src/libImaging/Resample.c) can change resize pass order for tall images. This implementation matches that reference behavior. The original Colab Pillow version was not supplied, so original-Colab byte/probability equivalence remains to be established. See also [ImageOps documentation](https://pillow.readthedocs.io/en/stable/reference/ImageOps.html).

The user reported a prior 16/16 Keras/TFLite prediction match and maximum probability difference of 3.4868717193603516e-06. Those results were not independently reproduced in this workspace. CQ093's source images and full probabilities are unavailable. No expected vector was invented.

## Real native smoke test and Colab comparison

The separate integration_test/hybrid_model_device_test.dart runs the real native model twice, checks seven finite probabilities and deterministic repeatability, and checks corrupt-model failure. It uses the existing background image as a runtime fixture and does not assert classification accuracy. It has not been run: no Android hardware or emulator is available.

Connect a physical Android device, install assets, enable airplane mode, then run:

    flutter test integration_test/hybrid_model_device_test.dart -d DEVICE_ID

Dart HTTP is blocked during the root-isolate smoke test, but this does not disable Android native networking; airplane mode is still required for a device-wide offline check.

To export a real fixture in Colab, run tool/export_hybrid_colab_fixture.py with the real model, JSON, side/end images and measured diameter:

    python export_hybrid_colab_fixture.py --model /path/to/quillgrade_hybrid_v2.tflite --config /path/to/hybrid_config_v2.json --side /path/to/side.jpg --end /path/to/end.jpg --diameter-mm 6.8 --output /path/to/exported_fixture

Copy the resulting files directly into assets/fixtures/hybrid_v2/, then run:

    flutter test integration_test/hybrid_model_device_test.dart -d DEVICE_ID --dart-define=HYBRID_FIXTURE_ASSET=assets/fixtures/hybrid_v2/manifest.json

This compares the model hash, config, preprocessed tensors and all seven probabilities. Its probability absolute tolerance is 1e-4, an explicit test bound rather than a measured equivalence claim. Without an exported fixture the comparison is explicitly skipped. The exporter was added but not run because TensorFlow and the real Colab source images are not available here.
